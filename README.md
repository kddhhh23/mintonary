# 민터너리 (Mintonary)

## 프로젝트 구조

```
mintonary/
├── app/     # Flutter 앱
└── server/  # Spring Boot 서버
```

## 브랜치 규칙

GitHub Flow를 따른다.

- **`main`** — 항상 동작하는 상태를 유지한다
- **`feat/기능이름`** — 기능 단위로 브랜치를 만들어 작업한다 (예: `feat/login`)
- 작업이 끝나면 `main`에 머지하고 브랜치를 삭제한다

## 커밋 규칙

형식: `타입: 설명` (설명은 한글로 작성)

| 타입 | 설명 |
|------|------|
| `feat` | 새 기능 추가 |
| `fix` | 버그 수정 |
| `chore` | 설정·잡무 (기능/버그 아닌 것, 초기 세팅·의존성 추가 등) |
| `docs` | 문서 작업 (README 등) |
| `refactor` | 기능 변화 없이 코드 구조만 개선 |
| `style` | 코드 포맷 정리 (들여쓰기 등) |
| `test` | 테스트 코드 |

- 한 커밋에는 한 가지 변경만 담는다
